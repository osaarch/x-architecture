## Motion theme (kinetic layer)

The site ships with a motion layer: `motion.css` + `motion.js` (linked from `index.html`).
It is always on: there is no switch in the header (the old pulse button and its saved `localStorage.xm` choice are gone;
`motion.js` deletes a leftover `xm` value). Only visitors whose device asks for reduced motion do not get it.

To go back to the classic look for everyone: delete `motion.css`, `motion.js` and the three tags that load them in
`index.html` (the `data-fx` bootstrap script in `<head>`, the `<link>` and the `<script src="motion.js">`).
The untouched classic version is also kept on the git branch `classic`.

## Header menu and the moving X
The header has no row of links: the small X mark (top, on every screen size) is the menu button (`#mnb`; its three polygons `#mxa/#mxb/#mxc` are tweened in JS). With a mouse, hovering it turns the X into three lines (the two triangles flatten into the top and bottom bars while a middle bar grows out of the centre) and the pages (Home, Services, Competitions, Library, Student work, Community, News, Contact, each with its number) drop out of it as plain links, staggered, with no box or border (`#mnp` / `#mn`; the page behind is only dimmed and blurred by `#mnk`). Moving the pointer away turns the lines back into the X and the links lift away. **On a computer (wide screen, real hover) a mouse click on the X goes Home** (a fresh load without the intro, like the "Home" link). On phones, tablets, any window 700px wide or narrower, with a finger, and with the keyboard, a click/tap on the X opens the same list instead (never reloads; "Home" is its first link) and a second tap, a tap outside, Escape, a link, or scrolling closes it (`hov()` decides); with the keyboard Enter opens it and arrow keys move between links. The current page is highlighted (`route()` sets `.on`); `prefers-reduced-motion` switches the morph and the stagger off. The code is the block after `lab()` that starts with "the X mark is the menu button"; its CSS is at the end of the main `<style>`. Add or rename pages in `#mn` (labels are translated like other static text; "Home" and the button label are set in `lab()`).

The X moves twice on a fresh visit: the big drawn X flies into the hero mark (where it always was) and stays there; after a second a **copy** of it flies up and becomes the small logo in the header (`fly()`, `land()`, `up()`, `fin()` in the intro script above the header; the flying copy is `#xfl`). While it travels the header mark is hidden (`html.xw`, "X waiting"). Visits that skip the intro (Home from the menu, a link with `#section`, reduced motion) show the header X at once. Over the header X the mark-shaped mouse pointer of `motion.js` steps aside, because the X itself reacts.

## Email confirmation
**Competitions (their own page: `#competitions` and `#competitions/<id>`; a project opened from there is `#competitions/p/<id>`; old `#community/c…` links redirect).** The page is the same code as the board (`community.js` has a *page mode*, `PM`/`pgShell()`/`pgDraw()`), so entering, likes, project view and sharing behave exactly as in the Community; the board's trophy button and the open-competition banner lead to it. The list of competitions is the file `competitions.json` at the root (the first two are in it: `iraqhouse`, a 250 m² house for Iraq's climate during the break between the semesters 2027-01-17 → 2027-01-30, and `myproject`, an open "show your project" competition 2026-11-02 → 2026-12-31; prizes say "announced later". With no object in the list the tab says "No competitions right now"; nothing is invented). To announce a competition, add an object to `competitions` and commit the file:

```json
{"competitions":[{
  "id":"pavilion1",
  "t":{"ar":"تصميم جناح صغير","en":"Design a small pavilion"},
  "d":{"ar":"وصف المسابقة…","en":"What the competition is about…"},
  "r":{"ar":["شرط أول","شرط ثانٍ"],"en":["First rule","Second rule"]},
  "pz":{"ar":"الجائزة أو التقدير","en":"The prize or recognition"},
  "start":"2026-12-01","end":"2026-12-31",
  "win":[]
}]}
```

`tpl` is optional too: a short text (up to 600 characters, per language) that fills the empty description box of the entry form when that competition is chosen, so the required details (idea, area, dimensions, location…) are not forgotten; what the person already typed is never replaced. `id` is 2 to 14 lowercase letters or digits; `t` (title), `d` (description), `r` (list of rules) and `pz` (prize, optional) are text per language (`ar`, `en`, and optionally `tr`, `fr`, `ku`; a missing language falls back to English, then Arabic); `start` and `end` are days in Baghdad time (the end day is included). The status (soon / open / closed) is worked out from the dates, so nothing else has to be switched. **Entries use the normal publishing system**: the "Competition" menu in the project window (or the Enter button) adds the hidden tag `xc:<id>` to an ordinary project, which goes through the same review (`CMOD`) and likes as every other project, so the Apps Script needs no change. An entry counts only if it was made between `start` and `end`, one per person (the first one); late or duplicate tagged projects simply do not show under the competition (they stay in the normal feed). The competition page lists the entries (newest or most liked) with the like count; when you have chosen the winners, put their project ids (the last part of the project link, `#community/p/<id>`) in `win` and they appear first with a "Winner" badge (even after they leave the newest-150 feed). The home page shows a banner at the top of the Community list while a competition is open. Chips never show the `xc:` tag.

**Profile photo.** The profile window (and the first registration form) has a picture row at the top: "Choose a photo" / "Change photo" / "Remove photo" (`rgphb()`, `rgphpick()`, `rgphset()`). The chosen picture is cropped to a centred square, scaled to 192px and saved as a small JPEG (about 10 KB; `rgphfit()`; any picture up to 15 MB is accepted, EXIF rotation respected) in `localStorage.xp` as `{u:<profile id>, d:<data URL>}`. It is **only on the visitor's device**: it is never added to the profile record, never posted to the server (`rgpay()` does not see it) and another profile id in the same browser does not inherit it (`rgphget()` checks the id and the data-URL shape). In the profile window a change is applied at once; in the first registration form it is kept in memory (`RPH`) and saved when registration finishes (`rgfin()`). Sign out removes it. The header button (`#usb`) shows it as a gold-ringed circle (`.uph`; the letter and the person icon hide while it is there). To make photos visible to other people later, the Apps Script (`backend/Code.gs`) would have to store them, which it does not do today.

Registration checks the address twice. In the browser `rgem()` rejects non-ASCII addresses, bad formats, common typo domains (`gmial.com` and so on, with a "Did you mean…" hint), disposable domains and impossible Gmail names. Then, when the Apps Script is version 2 or newer (`GET /exec` answers `v:2`, see `rgprobe()`), the script mails a 6-digit code (`vs`), the person types it (`vc`) and gets a signed token that is saved with the profile (`tok`) and is required by the `reg` action. If the script is still the old one the site falls back to the strict format check only; if the script cannot be reached an error is shown and nothing is saved. Setup steps are in `backend/SETUP.md` (section 6). By default the code is mailed from the Google account that owns the script (Apps Script cannot change the sender); to mail it from the site's own address (for example `no-reply@xarch.site`) the script can send through Resend once the two Script properties `RESEND_API_KEY` and `MAIL_FROM` exist (`sendMail_()` in `Code.gs`; steps and DNS records in `backend/SETUP.md`, section 7), or from a mailbox on the domain (for example Namecheap Private Email) through a Gmail "Send mail as" address, with the Script property `MAIL_ALIAS` (section 8; no third-party service, and the owner's personal address never shows). The render Worker does not check the token yet; add that before reopening the AI.
**A way to reach the person is required.** The registration (and profile) form asks for a **Telegram username or a phone number** (`#rg-contact`) and says why under the field ("One of the two is required: this is how we contact you directly"). `rgct()` in `index.html` accepts `@name`, `name`, `t.me/name` (Telegram names are 5–32 letters, digits or `_`) or a phone number of 7–15 digits (Arabic-Indic digits converted, `00` becomes `+`, spaces and dashes removed) and stores the clean value; `contact_()` in `backend/Code.gs` repeats the same rules, refuses a new registration without a valid contact (`err:'contact'`) and, for someone already on file, keeps the contact we have when an old page sends none. Redeploy `Code.gs` for the server-side check; the form check works without it.

**Community** (`#community`): an open **workspace** (Miro-style canvas) rather than a feed. The whole viewport is a pan / zoom / pinch board where a visitor drops, pastes or picks pictures, writes notes, **links a picture to a name with a connector** (rail button or `L`, then drag from one card to another; the connector carries a label), undoes (Ctrl+Z) and publishes the board. A search bar and a side drawer search **free sources** — Wikimedia Commons (CC licences, author and licence kept as the credit), the Art Institute of Chicago (public domain, IIIF) and Wikipedia — with an Arabic→English architecture dictionary, plus the community's own projects; results are added to the board by click or drag and keep their source link. **Drawing tools** (left rail, or keys `1`–`7`, `Esc` back to select, `Space` pans): freehand **pencil** (strokes are simplified and stored as short point strings), **shapes** (square, circle, line, arrow; `Shift` locks 45° / square), **people** figures (three styles, scale figures for plans), an **eraser**, a quick bar for stroke width / dash style / colour, duplicate, and a **canvas background** (plain, grid or dots, in three tones). Drawing cards are card kinds `d` (stroke), `s` (shape) and `h` (person) beside the picture / note / project / article kinds, so undo, selection, multi-select, links and publishing work on them unchanged; a board holds up to 400 cards and about 45,000 characters when saved. **Backend note:** `backend/Code.gs` (`cleanBoard_`) must be redeployed once for drawings and the background to be saved to the account or published; until then they stay on the device. On a new device a signed-in member's saved board is loaded from the server as soon as the feed check says the server is reachable (`srvWait()` in `community.js`), so the board is never shown empty while the account still has one. Everything works for guests locally (IndexedDB `board:<email|guest>`); publishing a project (up to 6 pictures) or a board needs a registered account and is moderated first (`CMOD='pre'`, approve from `admin.html`). The section is lazily loaded (`community.js` + `community.css`, by `rc()`; `window.CMOK` is its hook for route / language / sign-in). Deep links: `#community`, `#community/mine`, `#community/boards`, `#community/p/<id>`, `#community/u/<authorKey>`. Server side (`backend/Code.gs`, section COMMUNITY; setup in `backend/SETUP.md`, section 9): every write needs the signed registration token, is rate-limited and sanitised, and boards pass `cleanBoard_` (allowed card kinds, clamped numbers, image sources only from Drive or the allow-listed hosts, validated connectors). Until the script is redeployed the board and the free-source search keep working locally. No fake posts are seeded: empty states are shown instead.

## X Assistant (home page)
A small **full-body 3D character** (a boy or a girl, the visitor chooses with the face button in the chat header; the choice is kept in `localStorage` key `xas.ch`) lives on the **home page only** (`XAS.sync()` is called from `route()` and hides it on every other view). It waves hello on arrival, a bubble says "Hi! I'm X. What would you like to know?" with three quick questions (services, prices, contact), and tapping the figure opens a small chat. While it answers, its mouth moves. It can be **dragged anywhere on the screen** (mouse, touch, or Shift + arrow keys; the position is remembered and kept inside the screen, and the chat opens on the side that has room; the chat's title bar drags it too).
- **The 3D figure** is built in code (no model files, no images, no outside assets): `scripts/assistant3d.src.js` builds a low-poly character from spheres and capsules in three.js (MIT) and `assistant3d.js` is the bundled result, loaded lazily after the site's opening animation. It looks left and right (it follows the pointer, and glances around when idle), blinks, breathes, waves hello, moves its mouth while answering, is carried (arms out, legs swinging) when dragged and lands with a small squash, hops when the chat opens, and spins when the look is switched. Its colours come from the theme variables, so it follows dark + gold and light + gold. It sleeps after two quiet minutes, stops when the tab is hidden, and holds still with `prefers-reduced-motion`. If WebGL is missing, the file fails to load, Save-Data is on, or `localStorage` key `xas.3d` is `0`, the earlier flat 2D figure (drawn by `assistant.js`) is shown instead. To rebuild after editing the source: `bash scripts/build_assistant3d.sh` (needs Node and the npm registry), then raise `?v=` on `assistant3d.js` in `assistant.js`.
- Files: `assistant.js` (the widget, the flat fallback figures and the 3D hookup), `assistant.css` (theme variables only, so it follows dark + gold and light + gold), `assistant-core.js` (the matching engine, shared with the bot), `assistant-kb.json` (every answer, in Arabic, English, Turkish, French and Kurdish).
- **It is not an AI model.** It matches the question against keywords in `assistant-kb.json` and shows the prepared answer, so it can only say what the site says (real prices, durations, what is included, how to register). A question it cannot match gets a polite "message us" with the contact buttons. Services are not priced on the site, so the answers say to contact.
- To change what it says, edit `assistant-kb.json` (each intent has keywords `k`, answers `a`, links `l`), run `node scripts/test-assistant.js`, and raise `?v=` in the script tag. Nothing is sent anywhere and nothing is stored except the figure's place and look.

## Telegram and WhatsApp bot
`backend/bot-worker/` is a Cloudflare Worker that answers private messages on Telegram and WhatsApp with the same answers as the site's assistant (the language is detected from each message). `worker.js` is **generated**: run `python3 scripts/build_bot.py` after changing `assistant-core.js`, `assistant-kb.json` or `backend/bot-worker/glue.js`, then paste it into the Worker. Telegram uses a webhook with a secret-token check and replies inside the webhook response (the bot token is never in the Worker); WhatsApp uses Meta's Cloud API with the webhook verify token and an `X-Hub-Signature-256` check. Every secret is added by the owner in the Cloudflare dashboard, none is in the repository, nothing is stored or logged, and replies only carry the site link and the shared name `@xstudio4arch` (no `wa.me` link). Setup in Arabic: `backend/bot-worker/SETUP.md`. Tests: `node scripts/test-assistant.js` and `node scripts/test-bot.mjs`.

## Themes
Two themes are on the toggle: dark (black + gold, always the default on a fresh visit) and light (white + gold). The choice is kept per tab (`sessionStorage` key `xt`). Every colour comes from the theme variables (`--bg --bg2 --bg3 --ink --soft --line --gold --gold2 --ong ...`) set per theme in `index.html`; components never use a fixed colour, so a new page or component follows both themes by itself.

The mono (white + black) and red (white + deep red + grey) themes are paused: their CSS is still in `index.html`, and they come back by adding `'mono'` / `'red'` to `TH` / `THN` / `THC` (and a matching toggle icon). In the red theme the program icons on the Courses page are tinted red by a CSS filter and show their own colours while pressed, hovered or while their window is open (`pgHv()`).

**Future mode (`neo`) was retired.** The third theme (deep red, 3D models drawn on canvas, header clock) no longer loads: `neo.css` and `neo.js` were removed and the toggle only switches dark ↔ light. A visitor whose tab still holds `neo` in `sessionStorage` simply gets the dark theme. The full code stays in the git history (the `neo-theme` and `neo-polish` branches) if it is ever wanted back.

## Speed (why the site stays light)
- `index.html` carries no pictures: the lightbox uses the same `works/*.webp` files as the galleries (it used to embed 10 JPEGs as base64, ~2.8 MB). The page went from 3 MB to ~0.4 MB.
- Fonts are self-hosted (`fonts/`: TeX Gyre Adventor for Latin, Tajawal Arabic subset for Arabic/Kurdish, both free licences). Nothing waits for Google Fonts before the first paint.
- The hero loops are endless again, as designed: the hero glow, the breathing X, the floating triangles, the headline shimmer and the background glow never stop. To keep that cheap they pause while the hero is scrolled out of view (`html.hoff`, set by a small IntersectionObserver at the end of `index.html`; the rule is in `motion.css`) and the browser pauses them in a hidden tab. The motion layer's loop (`motion.js`, `wake()`) only runs while the pointer/scroll/hairlines move and sleeps ~0.5 s after. If a weak machine (or Edge with "Use graphics acceleration" off) still struggles, the visitor's device setting for reduced motion turns them off (there is no header switch any more).
